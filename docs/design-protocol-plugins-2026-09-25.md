## 1. 当前目标与边界

让真实的 Rust/rutis 插件和 TS/Cordis 插件，通过各自的上下文取得并使用对方的服务对象。真实对象留在创建它的进程，框架负责代理、调用与清理，作者使用生成接口。

本次交付只包含：

1. Rust 与 TS 双向原生服务注入，缺依赖时不运行插件。
2. 返回有状态对象、继续调用、传回创建者；保持对象身份。
3. 调用期间的借用回调，以及基础 parallel/serial 事件。
4. 正常启动、发布与卸载；释放、取消、断连和旧引用失效的必要正确性。
5. 用一个现有真实插件场景验证这些能力，记录必要的适配改动。

部署与运维编排、配置更新与升级回滚、组恢复、快照监督租约、详细管理诊断、共享/单成员布局比较、性能专项和完整组合故障矩阵，均从本次交付计划与验收中移除，不保留为本轮待办。

其他语言、第三方转交、持久业务回调、waterfall、流、网络远程接入和状态迁移也不属于本次范围。已存在的实验实现不自动成为交付要求。

## 2. 插件作者的使用方式

接口描述符生成两端客户端和导出适配器。业务提供者注册实际服务，消费者通过原生依赖注入取得生成的客户端。

下面表示适配后的调用形态，具体 API 以实现为准：

```ts
export const inject = ['database']
export async function apply(ctx: Context) {
  const connection = await ctx.database.connect({ name: 'main' })
  ctx.effect(() => () => connection.release())
  await connection.query({ sql: 'SELECT 1' })
  await ctx.database.inspect(connection)
}
```

```rust,ignore
let database = ctx.require_as::<DatabaseClient>(database_key.clone())?;
let connection = database.connect(Connect { name: "main".into() }).await?;
connection.query(Query { sql: "SELECT 1".into() }).await?;
database.inspect(connection.clone()).await?;
```

作者无需维护对象编号、JSON 路由或远端引用账本。已有本地服务与生成接口不同，则写一次明确的类型适配。

跨进程方法是异步的；同步属性访问、`instanceof`、任意反射和原型行为需要逐项适配。不变对象关系可以作为本地代理属性；可变关系使用异步方法。不承诺任意现有插件零修改兼容。

## 3. 最小实现结构

使用主进程 Host、Rust runner 和 Node runner，在本机 Linux 上通过私有 IPC 通信。

| 部件 | 职责 |
| --- | --- |
| Host | 固定服务路由、授权、调用中转、插件发布与失效 |
| Rust runner | 用真实 rutis 装载插件，管理本地依赖、上下文、effect 与子插件 |
| Node runner | 用锁定的 Cordis 发行包装载插件，管理本地注入、事件与清理 |
| 协议 SDK | 接口绑定、对象代理、导出表、编解码和资源归属 |

Rust runner 静态组合所需插件；Node runner 使用固定模块入口。首先验证一组固定的 Rust↔TS 服务关系，进程布局不构成比较或优化任务。

复用现有 rutis/Cordis 生命周期，不另造插件内核。适配层只补跨进程必要的门控、服务绑定和清理入口。使用到的 rutis 扩展必须注明来源与维护责任；Cordis 使用已锁定的 4.0.1 发行包。

对象调用统一经过 Host broker。私有连接区分协议与 stdout/stderr；接收泵允许回调重入，业务执行不持有 broker 锁。详细编码与既有 API 见[协议实现约定](../protocol/README.md)。

## 4. 核心语义

### 接口与对象

- Rust/TS 消费同一份接口 bundle 原字节，使用精确版本和 SHA-256 校验；生成绑定不依赖运行时反射。
- 数据、对象、回调及组合结构有明确编码。JSON 中形似对象编号的普通字段仍是数据。
- 同一真实对象重复返回，在同一导入范围和权限视图内保持代理身份；有环对象关系通过引用表表达。
- 对象身份绑定 owner、装载代与对象编号。旧代理不重新查找同名服务，不绑定新对象。
- Host 按调用者、接口视图及允许的方法验证授权；传回 owner 保持已授权视图，第三方转交拒绝。

### 引用与回调

- `scope` 对象归属插件或显式子范围；显式 release 关闭同范围别名，卸载兜底释放。
- `borrow` 引用只在一次调用及其登记任务存续期间有效；到期后保存的代理或回调明确失败。
- 交付引用与正在执行的调用独立持有资源。取消或丢弃等待者，不表示 handler 已结束。
- 正在执行的 handler 与登记任务完成后才释放执行引用。独占资源的 disposer 执行一次；错误保留为清理失败。
- A→B→A 回调可以重入，使用创建者的原始上下文，不阻塞接收泵。

### 发布、关闭与错误

1. 连接完成身份及契约检查；提供运行器就绪信号。
2. 原生依赖齐备后安装导入代理，装载真实插件；导出先暂存。
3. Host 核对导出并确认原生 Active，再开放调用与事件。迟到确认不能重开已关闭的代。
4. 停止或失效先关闭准入，再等待原生 effect、协议引用和登记任务的实际清理。

必要服务失效同时使相关消费者不可用；内部子插件继续由原生框架拥有。旧 Ctx 和旧代理不能登记或发起新操作。

连接断开即撤销该连接的服务与对象授权；未知或迟到旧消息不能复活引用。连接断开、超时、取消和句柄丢弃均不能冒充执行结束或清理成功。清理失败明确报错，未完成时保持关闭，不自动重新装载；本轮不提供更新或恢复入口。

错误至少区分参数/契约错误、权限拒绝、旧对象/关闭范围、取消、不可用与业务失败。两端对同一输入产生一致的错误含义。

### 基础事件

- 使用 Host 的唯一监听列表；本地框架通过适配器注册和移除监听，避免双重广播。
- `parallel` 并发执行有效监听并等待全部完成，汇总错误。
- `serial` 按权威顺序执行，以明确的 Continue/Return 表达短路；保留 `0`、`false` 等返回值。
- 监听归创建者装载代；注销先关闭准入，在途监听仍被跟踪。once 在进入前原子摘除，重入只执行一次。
- 订阅有 ready 确认；失效监听在执行前再次检查。scope 由 Host 授权，无法表达的过滤器拒绝。
- 载荷可含发布者自有对象，或传回接收者拥有的对象；不能借事件转交第三方对象。
- 同步跨进程 emit/bail、waterfall 和持久业务回调不支持，必须明确拒绝或显式适配。纯本地事件保留原行为。

## 5. 开发顺序

| 步骤 | 交付 |
| --- | --- |
| 1. 真实插件纵向 | 选定一个现有桥服务场景，完成原生注入、对象返回/继续调用/传回；验证双向使用 |
| 2. 对象与回调收敛 | 在同一路径验证身份、作用域、借用重入、释放、正常卸载及失效 |
| 3. 基础事件 | 接入 parallel/serial、ready、once、scope、注销与支持的对象载荷 |
| 4. 当前范围验收 | 核对迁移调用点与以下核心用例，完成可运行示例和必要使用说明 |

每一步以真实插件路径闭合，不用新写的 echo 样例代替现有插件适配。先使用已有基础；新增模块或公开 API 应指出哪一项核心用例存在缺口。

## 6. 完成定义

以下用例替代旧阶段表和验收矩阵；不要求把它们扩展为所有进程布局与故障组合。

| 用例 | 必须证明 |
| --- | --- |
| C01 原生双向注入 | 真正 rutis/Cordis 插件从本地上下文取得对方服务；缺依赖不进入业务 apply |
| C02 状态对象 | 两个方向均可返回、继续调用和传回对象；业务状态保持 |
| C03 身份与授权 | 重复返回、循环关系保持身份；视图权限有效；伪造和第三方转交拒绝 |
| C04 作用域与释放 | 同范围别名一起关闭，独立子范围互不误关；正常卸载释放引用；独占 disposer 一次且错误可见 |
| C05 借用回调 | A→B→A 无死锁，使用创建者上下文；登记任务完成前借用有效，之后拒绝 |
| C06 发布与失效 | 发布确认前不可调用；必要服务失效封闭消费者；旧 Ctx、对象和迟到确认不重开 |
| C07 等待与执行 | 丢弃/取消等待者后实际执行仍被跟踪；完成才释放执行引用；清理未完成不报告成功 |
| C08 基础事件 | parallel 等待、serial 顺序及 0/false 短路正确；ready、once、scope、注销与对象载荷有效 |
| C09 契约与断连 | 两端契约/值校验一致；不支持能力拒绝；断连撤销引用、迟到消息不复活 |
| C10 真实插件适配 | 一个现有插件场景实际运行；列出异步调用、属性、事件及清理的改动；旧桥必要回归通过 |
