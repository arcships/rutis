# 规则：不遍历祖先链的事件监听器关闭接纳（#1025）

[中文索引](../README.md) · [English](../README.en.md) · 数据来源：[事件关闭接纳设计](../../design-event-close-admission-2026-11-08.md) §3

本文件是手写的：设计 §3 的 10 条规则，编号 `ECA-<n>` 与设计里的规则号一一对应，一经分配不复用。级别按设计 §5 登记：规则 1–7、8、10 是 `events/lifecycle`（核心承诺，已登记）的内部机制——实现改动破坏接纳边界时，用户能看到关闭后仍被调用的监听器，所以按核心承诺登记；规则 9 说「开发者看到的行为不变」，按契约行为登记。

**状态：核心已实现，验证中（2026-11-09）。** 设计 §3 开头记着规则 1、2、5 的核心已实现，规则 3、6、7、8、9 的 Loading-owner、`once`、remote-entry、跨进程与重载覆盖尚未全部落地，所以设计仍不把这些规则写成「当前保证」。本表按实际证据分级：规则 1、2、4、5、8 有实现、确定性用例或 shuttle 模型，记「部分验证」（不写「已验证」——跨实现列、变异运行和 §6 全部门槛还没完成）；规则 3、6、7、9、10 记「未验证」。派工计划 §3 G3（`release_transient` 在 `Shared.admission` 外摘除 child）与 G4（shuttle 没有切换点）两条阻断已解除：摘除已在同一把锁下（`crates/rutis/src/fiber.rs:1477-1500`），marker 用 `crate::sync::AtomicBool`，模型能切换。

注意与登记表的层次差别：登记表的 `events/lifecycle` 行已随 #1025 改为「已验证」，它说的是用户能观察到的承诺（关闭后不再开始新的监听器调用）；本文件的 `ECA-*` 是这条承诺的实现层规则，剩余要点（`Loading` owner、`once` 不被消耗、接纳窗口、跨进程与重载）还没有用例，所以停在「部分验证」。
