# rutis 0.19.3

[English](0.19.3.en.md) · [0.19.2 发布说明](0.19.2.md)

0.19.3 修复 0.19.2 之后的几个 bug，并把 rutis 自己的两个服务改名。改名不兼容：用这两个服务的插件要改，见下面第一节和[迁移到 0.19](../migration-0.19.md) 的「0.19.3」。

## 先看这一处：rutis 自己的服务改名（不兼容）

- **`loader` 改为 `rutis/loader`，`sessions` 改为 `rutis/sessions`**（[#986](https://github.com/arcships/rutis/issues/986)、[#992](https://github.com/arcships/rutis/pull/992)）。`loader`、`sessions` 是宿主常给自己服务起的名字，现在留给宿主：宿主的行可以提供它们，测试也可以给插件假的服务。要改的只有用这两个服务的地方：插件（任何语言）的 `inject` 与 `ctx.use`（Go 是 `Inject` 与 `ctx.Use`）、`rutis.json` 里的 `isolate` / `inject`、命令里的 `rutis-host call loader.…`（改为 `rutis-host call rutis/loader.…`）。Rust 的连接插件、直接用 `Loader` 的宿主、`rutis-host/dial` 与 `rutis-host/listen` 行都不用改。旧名不保留，也不提示新名；完整对照表在[迁移到 0.19](../migration-0.19.md#0193rutis-自己的服务改名986)。

## 测试工具

- **回调与假服务调用交错时不再互相等死**（[#987](https://github.com/arcships/rutis/issues/987)、[#991](https://github.com/arcships/rutis/pull/991)）。TypeScript 测试里，测试同步调用插件交给它的函数、插件同时从另一条调用链调用测试的假服务时，两边以前一直等到进程被杀。现在两边都返回。只改测试工具自己用的两条会话，运行时与宿主之间的会话行为不变。Bun 与 Python 的同类问题仍开着（[#994](https://github.com/arcships/rutis/issues/994)、[#995](https://github.com/arcships/rutis/issues/995)）。
- **一次假服务撞名只让这次 `load` 失败**（[#988](https://github.com/arcships/rutis/issues/988)、[#993](https://github.com/arcships/rutis/pull/993)）。测试给的服务与宿主已有的名字撞上时，以前整个测试宿主断开，之后每个测试都报 `the host disconnected`；现在只有这次 `load` 失败，测试宿主照常服务后面的测试。

## 内核

- **dispose / shutdown 打断还在装载的插件时，清理错误回到结果里**（[#983](https://github.com/arcships/rutis/issues/983)、[#990](https://github.com/arcships/rutis/pull/990)）。这是 0.19.2（#969）的回归：预取消的一代回到 `Pending` 时，清理（回滚）错误只进了错误汇集，结果里看不到。现在预取消来自 dispose 或子树 shutdown 时，这一代直接卸载到 `Disposed`，清理错误由那次 `dispose()` / `shutdown()` 的结果返回；restart、update、驱逐仍回 `Pending`，清理错误进错误汇集。插件为配合取消返回的 `Err` 照诊断设计 D7 不报。

## 文档

- **插件 API 的事件例子在 Linux 上不再挂住**（[#984](https://github.com/arcships/rutis/issues/984)、[#989](https://github.com/arcships/rutis/pull/989)）。`serial` 加 `waterfall`（监听者调 `next`）的服务方法以前在测试里不返回，`npm test` 一直不退出；现在例子原样通过。修的是测试驱动的等待，不是事件本身。

## 行为变化

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| 插件的 `inject` / `ctx.use`、`rutis.json` 的 `isolate` / `inject`、`rutis-host call` | `loader`、`sessions` | `rutis/loader`、`rutis/sessions` |
| TypeScript 测试：调用回调与假服务交错 | 两边互等，`--test-timeout` 也不触发 | 两边都返回 |
| TypeScript 测试：假服务撞名 | 整个测试宿主断开 | 只有这次 `load` 失败 |
| `dispose()` / 子树 `shutdown()` 打断加载中的插件 | 清理错误只在错误汇集里 | 由结果返回，也留在终态上 |
| 插件 API 的事件例子（Linux） | `npm test` 不退出 | 通过 |
