# 外部事件队列接入口原型

状态：独立草稿，等待内核修改范围及调度成本评审；尚未获准合入。来源：[interop #73](https://github.com/arcships/rutis/pull/73)。此 PR 不含 IPC、生成器或 Cordis 改动。

## 接口决策

| 决策 | 行为 |
| --- | --- |
| 建根时注入 `EventQueue` | 接管一个事件 TypeId 的全部频道；未接管类型使用原存储；不允许运行时改变接管范围 |
| 仅替换存储和快照 | 原六种分发算法、短路、once、过滤、作用域及生命周期计数保持原语义 |
| 返回单监听句柄 | 外部队列可调用原 Rust 回调；句柄最多调用一次；next 的借用期由原调用持有 |
| 框架锁外调用适配器 | 登记 / 选择可能重入；返回后重新校验归属、类型、顺序资格及 active 状态 |
| 失败回滚 | 登记失败不留 effect；登记与卸载相遇时撤销外部条目 |
| API 稳定性 | 新接口与擦除续延公开标为 experimental；完整跨进程验证后再决定稳定接口 |

## 未完成的评审项

| 问题 | 原型现状与合入前要求 |
| --- | --- |
| 同步登记 / 选择 | `register` / `select` 均同步。真实 Cordis 队列会使登记、所有模式的快照选择（包括异步 `emit`）阻塞调用线程进行 IPC。该成本尚未验证，不能沿用“异步 emit 发出即返”的性能假设 |
| current_thread 等待 | 对端选择期间的同步回调可用关联消息泵推进；依赖被占用执行器的异步回调仍可能形成环。仅有队列接入口不能解决此问题 |
| 调度方案 | 完整接线前须比较异步选择入口与有序本地副本，并检查发出时快照、跨端登记顺序、once、注销和重入；本原型不声称已选出满足这些语义的方案 |
| 应用根创建 | 现有应用需将根创建改为 `Ctx::root_with_event_queue` 并提前给出接管范围。现有根迁移、包自动安装及动态类型发现均未实现 |
| 整个插件卸载 | 显式注销可以先外部清理再排空；原 fiber 卸载仍先等受计数事件再执行 effects。等待同 fiber disposer 的回调仍会卡住，不能扩大显式注销的保证 |

## 验证

[11 项测试](../crates/rutis/tests/event_queue.rs)对照原生与进程内外部队列：六种分发、按键顺序、once、pattern / 实例作用域、借用续延、单监听调用、无效快照、回滚与清理。

```sh
cargo test -p rutis --test event_queue --offline
cargo clippy -p rutis --all-targets --offline -- -D warnings
```

这些结果不代表真实跨进程队列的性能或完整事件兼容性。
